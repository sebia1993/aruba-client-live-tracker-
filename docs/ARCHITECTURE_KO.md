# 구조와 데이터 흐름

독립 패키지 `aruba_client_live_tracker`는 UI·수집·해석·상태 비교·저장을 분리합니다. 다른 저장소의 런타임 파일을 읽지 않습니다.

IP/MAC 검증 → Primary MM(통신 실패 시 Standby) → 후보 선택 → `Current switch`의 등록 MD 매핑 → 해당 MD 읽기 전용 조회 → 파서 → 대상별 Tracker → Qt 상세/목록·SQLite → CSV/HTML 순서입니다. 미등록 MD를 전체 탐색하지 않습니다.

`models.py`는 장비/대상/관측/이벤트 계약, `commands.py`는 입력 정규화와 허용 명령 생성, `parsers.py`는 알려진 출력 해석을 담당합니다. 불완전한 출력을 미등록 0건으로 바꾸지 않습니다. `collector.py`는 MM→MD 라우팅과 지표 수집, `ssh.py`는 서버 키·타임아웃·출력 상한을 관리합니다.

## 다중 수집

`monitoring.py`의 Qt 비의존 coordinator가 최대 10개 대상 context를 관리합니다. 각 대상은 고유 ID·세대·Tracker·collector·세션·취소 신호·마지막 결과·다음 시각과 독립 버퍼를 가집니다. 상태는 중지/실행/일시 정지/후보 선택/중복 대기로 구분합니다. 중지·제거 시 세대를 무효화하여 늦게 끝난 결과가 다른 대상에 섞이지 않게 합니다.

ThreadPoolExecutor 워커와 실제 제출 작업은 전체 최대 2개입니다. 워커는 수집만 하고 완료 큐를 주 스레드의 `tick()`이 처리하여 UI와 SQLite를 갱신합니다. 대상은 공정하게 순환하고 다음 조회는 완료+공통 주기로 계산합니다. 중복 작업을 누적하지 않습니다. 한 대상의 오류·후보 대기·취소가 다른 대상의 상태를 덮어쓰지 않습니다.

`session_pool.py`는 공유 SSH 연결을 최대 12개로 제한하고 장비별 명령을 직렬화합니다. 수집기는 소유자별 runner를 사용하고 종료 시 자기 소유만 해제합니다. 네트워크 실패 뒤 15초 재시도 대기를 적용합니다. 최초 서버 키 승인은 UI 큐로 전달하며 변경된 키를 자동 승인하지 않습니다. 취소와 승인은 소유 대상에 귀속됩니다. 기존 단일 추적 경로도 유지합니다.

`tracker.py`는 정상 관측 사이의 연결/로밍/정책/품질 변화를 판정합니다. 오류이면 마지막 유효 값을 보존하고 비교 연속성을 끊습니다. 그래프는 대상별 최대 240개, 이벤트 버퍼는 500개로 제한합니다.

## 저장과 배포

`storage.py`는 기존 SQLite 스키마와 단일 export API를 유지하면서 여러 세션을 대상·세션 식별 및 시각과 함께 CSV/HTML로 내보냅니다. 대상 목록은 메모리만 유지하고 수집 이력은 영구 저장합니다. 장시간 실행하면 DB 크기가 증가합니다. `demo.py`는 같은 수집 인터페이스로 대상마다 독립 가상 시나리오를 제공합니다.

비밀번호는 실행 중 메모리에만 존재합니다. 원문 CLI와 보고서는 로컬 정보이며 공개 로그나 Git에 넣지 않습니다. PyInstaller onedir 배포는 Qt DLL을 동적으로 유지하고 `SOURCE`에 새 모듈·테스트·문서·빌드 워크플로를 재귀적으로 포함합니다. Windows Actions는 실제 단일/10대 EXE 스모크 결과 JSON을 보존하도록 구성합니다.
