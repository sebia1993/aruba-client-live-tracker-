### 진행 파일 경합 재현과 수정

별도 Windows 합성 파일 시험에서 Python 읽기와 원자 교체의 동시 실행으로 `PermissionError`가 실제 발생함을 확인했습니다. 실제 파일 공유 잠금을 이용한 회귀에서도 읽기·교체 두 경계가 수정 전 실패했습니다. 또한 파일 mtime을 확인한 뒤 다른 버전의 내용을 읽는 경쟁 조건 때문에 같은 정상 heartbeat를 다시 읽으면 정지로 오판하는 경로도 별도 자식 프로세스로 재현했습니다.

기록기는 권한 오류만 최대 1초·51회 범위에서 재시도하며, JSON 내용의 heartbeat/경과 시간으로 진행 여부를 판정합니다. 완전히 같은 버전은 watchdog을 연장하지 않고 무시하며, 역행·식별자 변경·한 필드만 증가하는 경우는 실패합니다. 지속 오류에는 민감한 원문 없이 단계·errno·winerror·시도 횟수를 기록합니다. 앱의 진행 저장은 첫 권한 오류부터 고정 5초 동안 tick당 한 번만 시도해 GUI를 막지 않으며, 지속 거부·다른 I/O 오류·잘못된 JSON은 실패 처리합니다.

수정 전 실패를 확인한 뒤 기록기 관련 71개와 앱 soak 19개가 통과했습니다. 진행 파일 수정 중간 빌드 ID는 `0.3.8-93cf1802cf17`입니다. 전체 빌드 검사에서는 아래의 별도 SSH 키 파일 오류가 발견돼 EXE 생성 전에 중단했습니다. 이전 `0.3.8-2a8590e961c7` 실행과 ZIP 증거는 새 수정본의 장시간 검증을 대신하지 않습니다. 추적용으로 실행한 이전 빌드의 300초 진단은 301.922초에 통과했으며 예외가 재발하지 않아 원래 188초 오류의 정확한 위치는 여전히 미확정입니다.

키 사전 읽기는 기존 키 저장 잠금 밖에서 수행되고 있었습니다. 별도 회귀에서 실제 Windows 공유 거부 핸들과 키 저장 경계를 겹쳐 `KNOWN_HOSTS_INVALID`(원인 `PermissionError`, errno 13)를 재현했습니다. 사전 읽기를 취소·기한 제한이 있는 기존 잠금으로 보호하고, 잠금 해제 뒤 네트워크 접속 전에 취소·기한을 다시 검사하도록 수정했습니다. 초기화 5개 단계와 teardown assertion 실패에서도 획득한 테스트 자원을 정리하도록 보완했고, 회귀 6개가 수정 전 실패·수정 후 통과했습니다. 손상된 키 파일을 허용하거나 초기 실패를 재시도로 숨기지 않습니다. 실패한 JUnit 원본은 `artifacts/pytest-windows-build-io-first.xml`에 보존했습니다. SSH 범위 검사 96개와 별도 자원 정리·실제 종료 검사 7개도 통과했습니다.
