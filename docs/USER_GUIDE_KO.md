# 초급 엔지니어 사용 설명서

## 무슨 문제를 확인하는 도구인가요?

최대 10대 단말의 담당 AP/MD, 접속 정책(Role), 신호 품질 변화를 함께 봅니다. 10~60초 간격 사이의 짧은 끊김이나 로밍은 놓칠 수 있습니다. PHY Rate는 실제 파일 전송 속도가 아닙니다.

## 간편 설정과 장비 발견

전체 추적을 중지한 뒤 장비 설정에서 MM 이름/IP와 공통 SSH 계정을 입력하고 장비 찾기를 실행합니다. MM의 `show switches` 결과가 목록에 표시되며 입력한 MM이 기본 선택됩니다. 추가 검사할 장비를 체크하거나 전체 선택한 뒤 **선택 장비 검사**를 누릅니다. 선택한 주소에만 접속하여 `show version`·`show switchinfo`를 확인합니다. 목록 조회는 자동 반복하지 않습니다.

역할·모델·버전·관리 주소와 진단을 검토한 뒤 **선택 장비 등록**으로 설정에 반영합니다. 검사 후 선택을 바꾸면 다시 검사해야 등록할 수 있습니다. 기존 수동 유형·관리 주소·MD 매핑은 발견 정보로 덮어쓰지 않습니다. 합치기 충돌은 진단에서 확인합니다. 설정 저장은 장비 설정 창에서 완료합니다. 기존 수동 설정도 사용할 수 있습니다.

`Type` 등 명시적인 역할 근거로만 Primary/Standby MM과 MD를 확정합니다. 이름이나 모델만으로 역할을 추측하지 않으며 `판별 불가 (AUTO)` 장비는 추적에서 제외합니다. 이전 문서의 `master/local` 예시도 ArubaOS 8의 Primary 근거가 되지 않습니다. 판별 불가이면 실제 구성에 맞게 수동 역할·관리 주소·`Current switch` 매핑을 검토합니다.

장비 모델과 역할은 별도 정보입니다. 수동 지정이 필요하면 다음 기준을 사용합니다.

| `show switches` Type | 장비 유형 | 대표 모델 |
|---|---|---|
| conductor | MM_PRIMARY | ArubaMM-HW-10K |
| standby | MM_STANDBY | ArubaMM-HW-10K |
| MD | MD (WLC) | Aruba7240XM, Aruba7210 |

기존에 잘못 지정한 수동 유형은 자동 발견으로 덮어쓰지 않습니다. 해당 장비를 **수정**하여 자동 판별(AUTO)로 바꾼 뒤 **선택 장비 판별**을 실행하거나, 확인된 Type에 맞게 수동 수정하십시오. 관리 IP가 `Current switch` 주소와 다르면 담당 MD 매핑에 식별 주소를 보존합니다.

공통 SSH 계정은 실행 중 발견과 추적에서 재사용하고 파일에 저장하지 않습니다. 종료나 계정 변경 시 참조를 폐기합니다. 최초 서버 키는 질문이나 별도 동의 옵션 없이 로컬에 자동 저장하며(TOFU), 이후 키나 알고리즘이 바뀌면 인증 전에 차단합니다. 기존 `known_hosts`는 유지됩니다.

## 단일 추적

IPv4 또는 MAC을 입력합니다. `aa:bb:cc:dd:ee:ff`, `aa-bb-cc-dd-ee-ff`, `aabb.ccdd.eeff`와 대소문자를 지원합니다. 여러 후보가 나오면 IP/MAC/담당 MD를 확인하여 선택합니다. 다른 검색값으로 시작하면 새 세션을 만듭니다.

## 다중 모니터링

추적 방식을 다중으로 전환하고 IPv4/MAC을 한 줄씩 등록합니다. 최대 10대이며 잘못된 줄과 중복 항목은 메시지를 확인하고 수정합니다. 목록에서 행을 선택하면 그 대상의 접속 정보·그래프·이벤트·진단을 봅니다. 선택만 바꾸어도 다른 대상의 수집은 계속됩니다.

선택한 대상에 개별 시작/중지/일시 정지/재개/새로고침을 적용하거나 전체 버튼으로 일괄 제어합니다. 중지는 진행 중 작업을 취소하고 세션을 끝냅니다. 일시 정지는 다음 자동 조회를 멈추며 재개로 이어갑니다. 즉시 새로고침은 작업을 중복해서 쌓지 않습니다. 조회 주기는 공통 10/15/30/60초이고 완료 시점부터 계산합니다. 전체 수집을 최대 2개씩 순환하므로 대상과 장비 응답이 많으면 조회 간격이 길어질 수 있습니다.

동일 MAC으로 해석된 대상은 먼저 등록된 활성 항목을 우선하고 중복 항목을 대기시킵니다. 후보 선택이 필요한 항목이나 한 대상의 조회 오류는 다른 대상의 수집을 막지 않습니다. 최초 서버 키는 자동 저장되며 변경된 키는 연결을 차단합니다. 키 오류는 대상별 진단에서 확인합니다.

대상 제거 전에 중지하고 필요한 이력을 내보내십시오. 목록은 저장하지 않으며 프로그램 종료 후 다시 등록해야 합니다. 이미 수집한 이력은 SQLite에 남습니다. 데모/실장비·추적 방식·장비 설정은 전체 추적을 중지한 후 변경합니다.

## 화면 읽기

- **현재 접속 정보:** MM의 MAC·담당 MD와 MD의 AP/SSID/Role/VLAN입니다. 확인되지 않은 값은 `확인 불가`입니다.
- **이전 조회값:** 이번 수집이 실패하여 마지막 정상 값을 보존한 상태입니다. 마지막 조회와 마지막 유효 관측 시각을 비교하십시오.
- **SNR:** 신호와 잡음의 차이(dB)로 보통 높을수록 유리합니다. 마지막 수신 패킷 기준일 수 있으며 단독으로 장애 원인을 확정하지 못합니다.
- **RSSI:** 실제 dBm 필드가 확인될 때만 표시하며 ClientMatch 과거 값으로 대체하지 않습니다.
- **Tx/Rx PHY Rate:** 무선 링크의 물리 속도입니다. 실제 처리량이 아니며 방향은 CLI 출처를 확인합니다.
- **Role:** 인증 후 적용되는 접근 권한 정책으로 인증 변경과 함께 봅니다.
- **재전송률:** 같은 AP/MD의 호환되는 연속 카운터 차이로 계산합니다. 리셋·누락·로밍이면 연속 계산을 끊습니다.

연속 정상 관측의 AP/BSSID 변화를 로밍 관측으로 기록합니다. 표시 시각은 이동 시각이 아닌 감지 시각입니다. SSH 오류를 로밍/연결 해제로 바꾸지 않습니다. 이벤트의 관측 사실·추정 원인·권장 확인 항목을 구분하십시오.

## 단계별 진단

예전의 포괄적인 `MD 조회 실패`만으로 원인을 판단하지 말고 단계·코드·장비·명령·안내를 함께 보십시오. 연결, 서버 키, 인증, 장비 발견, 역할 식별, MM 조회, MD 매핑, MD 명령, 출력 해석, 무선 조회와 로컬 저장 실패를 구분합니다. SSH 실패는 단말 해제를 뜻하지 않습니다. 사용자가 겪은 MD 실패의 실제 원인은 아직 미확정이며 자동 등록이 그 원인을 해결했다는 뜻은 아닙니다.

## 이력과 내보내기

이력에서 세션과 기간을 선택해 대상별 CSV/HTML로 내보냅니다. 다중 모드의 통합 내보내기는 여러 대상의 세션을 함께 저장하고 대상·세션 식별자와 수집 시각을 구분합니다. 삭제·재등록 등으로 생긴 과거 세션은 이력에서 따로 확인합니다. 실패한 수집도 정상 값과 구분하여 남고 단계별 진단을 CSV/HTML에 함께 내보냅니다. 기존 DB는 진단 컬럼을 자동 추가하며 과거 행의 진단은 빈 목록으로 유지합니다. 설정 v1은 계속 읽고 새 저장은 장비 식별 정보를 포함한 v2로 기록합니다.

HTML은 오프라인에서 볼 수 있으며 CSV는 수식으로 해석될 수 있는 문자열을 보호합니다. 보고서는 로컬 파일이지만 운영망 정보가 포함될 수 있으므로 접근 권한을 관리합니다.

## 데모 모드

가상 데이터 배너를 확인하십시오. 정상 접속·IP/SNR/전송률 변화·AP/Role 변경·재전송·해제/복구·MM/MD 오류·담당 MD 변경·출력 형식 오류·중복 후보를 재현합니다. `--multi-demo`는 10개 독립 가상 대상을 준비합니다. 실제 Aruba 출력이나 실장비 성능 검증은 아닙니다.
