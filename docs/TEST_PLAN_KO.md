# 테스트 계획과 검증 경계

## 자동 검증

```powershell
python -m pytest -q
python -m ruff check src tests scripts
python -m aruba_client_live_tracker.main --demo --smoke-test --data-dir smoke-data
pwsh -File build_windows.ps1
```

테스트는 운영망에 연결하지 않습니다. 합성 CLI와 가짜 SSH 전송을 사용합니다. 실제 결과와 개수는 `BUILD_VALIDATION_KO.md`를 보십시오.

| 영역 | 확인할 실패 경계 |
|---|---|
| 입력/명령 | IPv4 범위, MAC 세 형식, 줄바꿈/따옴표/명령 연결 주입 차단 |
| 파서 | MM 중복/빈 결과, 잘린 표/알 수 없는 형식, MD 필드와 무선 단위 |
| 라우팅 | Current switch 정확한 매핑, 중복 매핑 거부, 미등록 MD 전체 검색 금지 |
| SSH | 최초 키 승인/거절, 변경 키 차단, 취소/타임아웃/출력 상한/세션 정리 |
| 상태 | 연속 정상 관측 로밍, 조회 실패 전후 오판 방지, Role/VLAN 변경 |
| 카운터 | 증가/리셋/AP 변경/누락 시 차분 처리, 불명확한 재전송률 미생성 |
| 저장/보고서 | 세션 종료, 실패 보존, 기간 필터, HTML/CSV 삽입 방지 |
| GUI | 데모 시작/중지/새로고침/대상 전환, 실제 창 생성, 주 스레드 응답 |
| 지속 수집 | 반복 관측의 버퍼/연결/메모리 상한 |
| 배포 | Windows PE x64 EXE, frozen GUI 데모 프로세스 종료 코드, ZIP/DLL/고지 |
| 공개 자료 | 비밀 키/토큰/운영 데이터 파일 미포함, RFC 5737 예시 주소 |

데모 시나리오는 정상 접속, IP/MAC 검색, IP 변경, SNR 저하, Tx/Rx 변동, AP 로밍, Role 변경, 재전송 급증, 해제/재연결, MM/MD 실패, 담당 MD 변경, CLI 형식 변경, 잘못된 MAC, 중복 후보를 다룹니다.

## 사용자가 실제 장비에서 확인할 절차

1. 테스트용 권한의 SSH 계정을 사용하고 장비 관리자가 확인한 키 지문과 비교합니다.
2. MM Primary/Standby와 모든 필요 MD의 관리 주소 및 매핑을 등록합니다.
3. 알려진 한 단말의 IP/MAC 양쪽 검색 결과가 같은 단말인지 확인합니다.
4. CLI 문서의 명령별 실행 위치/인자/권한을 ArubaOS 8.10 세부 버전에서 확인합니다.
5. AP/SSID/Role/VLAN과 실제 CLI 값을 비교합니다. 필드 출처·단위·Tx/Rx 방향을 확인합니다.
6. 신호·전송률을 같은 시각에 비교합니다. 과거 SNR/ClientMatch 값인지 구분합니다.
7. 단말을 이동해 AP 변경과 로밍 전후 값, 관측 간격의 한계를 확인합니다.
8. 테스트용으로 SSH 경로만 차단했을 때 단말 해제가 아닌 수집 실패로 보이는지 확인합니다.
9. 승인된 절차로 MM 장애 전환/MD 변경을 재현하고 연결 정리를 확인합니다.
10. Windows 11 1366×768, 125% 및 150% 배율에서 설정·검색·이력·내보내기를 확인합니다.
11. 일반 사용자 권한에서 장시간 실행하고 파일/메모리/장비 부하를 확인합니다.

실제 장비 테스트는 사용자가 수행합니다. 이 프로젝트 작업자는 운영망 계정/주소/출력을 요청하거나 저장하지 않았습니다. 결과 공유 시 원문·주소·SSID·사용자 정보를 비식별화하십시오. Wine에서 Windows EXE를 실행한 결과는 Windows 11 실기 검증을 대체하지 않습니다.
