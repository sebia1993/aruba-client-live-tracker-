# 오류별 점검 방법

| 표시/증상 | 의미와 다음 확인 |
|---|---|
| 등록 형식 오류 | IPv4/MAC을 한 줄에 하나씩 입력합니다. 포트·명령어를 넣지 않습니다. |
| 10대 한도 | 기존 대상을 중지·제거한 뒤 등록합니다. 이력은 SQLite에 남습니다. |
| 중복 대상/동일 MAC 대기 | 같은 단말의 IP/MAC이 함께 등록되었는지 확인합니다. 먼저 활성화된 대상을 유지하고 중복 항목을 정리합니다. |
| 여러 후보 | IP 재사용/중복 등록 여부와 MAC·담당 MD를 확인하여 선택합니다. |
| 다른 대상 상세가 보임 | 목록에서 해당 행을 선택합니다. 선택 전환과 수집 시작/중지는 별도입니다. |
| 실행 후 목록이 비어 있음 | 대상 목록은 저장하지 않습니다. 다시 등록하고 기존 세션은 이력에서 확인합니다. |
| 모드/설정을 바꿀 수 없음 | 전체 추적을 중지하고 진행 중 수집이 정리될 때까지 기다립니다. |
| MD 매핑 없음 | MM의 Current switch 값과 등록 MD의 관리 주소·매핑을 대조합니다. 누락이면 해당 MD 매핑을 수정하고 충돌이면 임의 장비를 선택하지 않습니다. |
| SSH 연결 실패 | 관리 주소/포트/경로/계정을 확인합니다. 단말 연결 해제라는 뜻이 아닙니다. 실패 후 재시도 대기가 있습니다. |
| 최초 서버 키 질문이 없음 | v0.3.0은 최초 키를 자동 저장합니다(TOFU). 별도 승인이나 opt-in 단계가 없습니다. |
| 신뢰 키 저장/잠금 실패 | 로컬 데이터 폴더 쓰기 권한과 다른 프로세스 잠금을 확인합니다. 저장 실패는 인증 전에 차단합니다. |
| 발견 목록이 없음 | 발견 단계의 코드와 `show switches` 권한·출력 형식을 확인합니다. 목록 실패를 장비 0대로 단정하지 않습니다. |
| 판별 불가 (AUTO) | 명시적인 역할 근거나 자기 식별을 확인하지 못했습니다. 이름/모델/master/local로 추정하지 않으며 수동 역할·관리 주소·매핑을 검토합니다. |
| 선택 장비 등록이 비활성 | 장비를 선택한 뒤 검사합니다. 검사 후 선택을 바꾸면 다시 검사해야 합니다. |
| 발견 정보 병합 충돌 | 기존 수동 유형·관리 주소·MD 매핑을 보존합니다. 진단을 확인하고 실제 구성에 맞게 수동 수정합니다. |
| 계정을 다시 입력해야 함 | 공통 계정은 실행 중에만 재사용합니다. 앱 종료나 계정 변경 후 다시 입력합니다. |
| 서버 키 변경 | 자동 연결을 차단합니다. 실제 교체/키 변경을 관리자에게 확인합니다. 신뢰 파일을 무작정 삭제하지 않습니다. |
| 명령 지원 안 함/출력 형식 확인 불가 | ArubaOS 버전·역할·CLI 권한·잘린 표를 확인합니다. 알 수 없는 출력을 미등록으로 보지 않습니다. |
| 이전 조회값 | 이번 수집 실패로 마지막 유효 값을 보존한 상태입니다. 마지막 유효 시각을 봅니다. |
| RSSI/전송률 확인 불가 | 값 또는 단위가 검증되지 않았으며 추정값을 채우지 않습니다. |
| 다중 조회/그래프 간격이 길어짐 | 전체 수집은 최대 2개씩 순환하며 완료+주기를 적용합니다. 느린 장비와 대상 수를 확인합니다. |
| 저장/내보내기 실패 | 로컬 디스크 공간·쓰기 권한·다른 프로그램의 파일 잠금을 확인합니다. |
| EXE 실행 안 됨 | Windows x64·ZIP 전체 해제·DLL 누락·보안 제품 차단을 확인합니다. |
| 재빌드 폴더 정리 실패 | 기존 EXE와 관련 프로세스를 종료한 후 다시 빌드합니다. |
| 글자/버튼 잘림 | 창을 확대하고 스크롤·Windows 배율을 확인합니다. |
| 이력 파일이 커짐 | 종료 후 보고서를 내보내고 DB를 별도 보관합니다. SQLite는 로컬에 누적됩니다. |

진단의 단계·코드·장비·명령·안내를 함께 확인하십시오. 연결/키/인증, 발견/식별, MM 조회, MD 매핑/명령, 해석/무선, 저장 실패는 확인할 위치가 다릅니다. 이전의 `MD 조회 실패` 문구만으로 사용자가 겪은 실제 원인을 확정할 수 없으며 자동 등록만으로 해결 완료라고 볼 수 없습니다.

지원 요청은 버전·Windows 버전·비식별화한 재현 단계와 오류 분류부터 공유합니다. 실제 비밀번호·원문 인증 로그·내부 SSID·운영망 스크린샷을 공개하지 마십시오.

## 장비 찾기에서 SWITCH_TABLE_PARSE_FAILED

v0.3.2는 `show switches`가 장비 표와 Status/Configuration State 표를 나누어 출력하면 두 번째 머리글을 IP 행으로 읽어 실패했습니다. v0.3.3에서 이 형식을 지원합니다. 업데이트 후에도 실패하면 오류 뒤의 세부 사유로 머리글/행 수/완료 건수를 구분하십시오. 실제 주소·계정·CLI 전체 원문을 공개 이슈에 올리지 마십시오. 이 오류를 해결하기 위해 장비 설정이나 SSH 권한을 무작정 변경할 필요는 없습니다.

v0.3.4는 공식 AOS 8.10 문서에 있는 `IP Address=None`/IPv6 주소 행도 지원합니다. 이는 확인된 형식 지원 누락을 수정한 것이며 모든 IP 형식 오류의 원인을 의미하지 않습니다. 여전히 실패하면 오류 안내의 출력 행 번호와 IP/IPv6 열 길이로 어느 위치를 해석하지 못했는지 로컬에서 확인할 수 있습니다. 이 안내에는 해당 셀의 실제 주소나 원문을 넣지 않습니다.

`선택 장비 검사`는 `show switchinfo`와 `show version`만 실행합니다. 따라서 검사 후 보이는 `SWITCH_TABLE_PARSE_FAILED`는 앞선 MM 목록 조회의 오류일 수 있습니다. 진단은 현재/이전 작업과 검사 회차를 구분하고 이전 MM 오류를 계속 표시합니다. 선택 장비 검사가 끝났어도 목록 조회가 복구된 것은 아닙니다. 자동 발견이 실패한 상태에서는 장비 설정 화면에서 확인된 MM/MD 유형·관리 주소·매핑을 수동 등록할 수 있습니다.
